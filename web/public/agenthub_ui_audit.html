Critical issues — fix these first
DASHBOARD High priority
Empty dashboard has no direction
Zero stats with no guidance creates a "broken" feeling. Users don't know what to do and may churn on day one.
Fix: Add a checklist-style onboarding card: "Complete your setup" — connect Gmail, run your first service, invite a friend. Disappears once done. Show 0 values with a helpful nudge like "Run a service to see stats."
SETTINGS High priority
Dead-end connection statuses
"Not connected" and "Not authenticated" are shown with no action. Users are stuck — there's nowhere to click to fix this.
Fix: Each connection row needs a Connect or Authenticate button inline. Show a subtle status dot (green = connected, amber = partial, red = error). Add a short tooltip explaining what each connection unlocks.
SETTINGS High priority
Danger Zone is too close to normal settings
Delete Agent sits in the same visual flow as Save and Restart — a scroll-past risk with no buffer.
Fix: Add at least 60px of whitespace + a full-width divider before the Danger Zone. Optionally place it in its own card with a warning background tint. Add a confirmation dialog with typed confirmation (e.g. type agent name to delete).
PRICING Medium priority
"Current Plan" is shown on Enterprise
If the user is not on Enterprise, showing "Current Plan" on that tier is misleading and potentially alarming.
Fix: Read the user's actual plan from their session and apply the "Current Plan" badge dynamically. Highlight the right card programmatically.
SERVICES Medium priority
"Run" button gives no feedback or preview
All five services have identical "Run" CTAs. Users don't know if clicking opens a form, starts a job, or navigates away.
Fix: Change "Run" to an action-specific label: "Generate Report", "Triage Inbox", "Analyze Paper". On hover, show a tooltip or a mini-preview of what the service does. On click, show a loading state before navigation.
REFERRAL Medium priority
Referral code not shown by default
The code input is empty on page load. This makes the feature feel broken and reduces sharing motivation.
Fix: Auto-generate and pre-fill the referral code on load. Show "0 friends referred / 0 free weeks earned" with real zeros (not blank tiles). Add a share button (WhatsApp, copy link) alongside the Copy button.
Missing features & UX gaps
No notification system
When an agent completes a job, there's no way for the user to know. No in-app notifications, no email confirmation shown, no history log.
Add: A notification bell in the nav. A "Job completed" toast on service finish. An activity log on the dashboard with timestamps and statuses.
No profile or account page
Settings has an Agent tab and Referral tab but no Account tab visible in the live app (seen in settings nav: Agent, Account, Referral — Account is there but not shown).
Ensure: Account tab shows name, email, plan, billing date, and a logout button. This is critical trust infrastructure for a paid SaaS.
No output viewer
Where do users see the results of a service run? There's no output page, results panel, or download flow visible in any screenshot.
Add: A results drawer or dedicated output page per service run. Show formatted output (LaTeX preview, email drafts, summaries). Allow download as PDF or copy.
No help or docs link
No FAQ, no onboarding tooltip, no "How it works" walkthrough anywhere inside the authenticated app.
Add: A small "?" icon in the nav linking to docs. A first-run walkthrough tooltip sequence. An inline help icon next to "LiteLLM Key" and other technical fields.
Mobile responsiveness unclear
The landing page nav collapses poorly at smaller viewports based on the screenshot layout. Services grid may not wrap well on mobile.
Verify: Test all pages at 375px and 768px. The 3-column services grid should go 1-column on mobile. Nav needs a hamburger menu for small screens.
Agent uptime shows "—"
A dash instead of "0h" looks like a loading error, not an intentional empty state. Erodes trust in the platform's reliability.
Fix: Show "0h" or "Just started" with a tooltip. Once uptime exists, show it as "3h 22m" not a raw number. Consider a small uptime sparkline over 7 days.
Aesthetic improvements
Current
Typography: Multiple font weights used inconsistently across pages. Title sizes vary between the landing page and inner app.

Color: The blue (#2563EB-ish) is used for all interactive elements but there is no secondary accent. Everything feels monotone.

Spacing: Card padding is tight on the landing page feature grid. Inner app cards feel more generously padded — inconsistent rhythm.

Hero image: Generic robot stock photo unrelated to the actual product.
Recommended
Typography: Lock in two weights only: 400 body, 600 headings. Use one type scale across all pages (e.g. 14/16/24/32px).

Color: Keep blue as primary. Add a warm neutral (slate/stone) as a surface color and one accent (e.g. teal or violet) for success states and feature highlights.

Spacing: Define a 4px base unit. Use 16/24/32/48px consistently. Landing and app should share the same padding scale.

Hero: Replace the stock photo with a live demo GIF or animated mockup showing the actual agent running a task.
Tone & branding
The product has great bones — it just needs a stronger identity
AgentHub currently reads as a clean but generic B2B SaaS. Given it targets university students, you can afford to be warmer and more specific. Consider a mascot or named agent persona (like the "UNIT 754" branding on the robot — lean into this). Use the agent's name throughout the app ("UNIT 754 is ready", "Ask UNIT 754 to..."). This creates emotional attachment and differentiates from enterprise AI tools.
